# TailView

TailView is a private, experimental Mac screen and audio bridge for an iPhone or iPad. The Mac app runs in the menu bar. An already paired device connects when its iOS app opens, shows the main Mac display, plays Mac app and media sound, sends its microphone to BlackHole 2ch, and can use the Mac mouse and keyboard. TailView sends data directly over the existing Tailscale connection; it has no account service or Jump Desktop dependency.

## Build and install

Run `xcodegen generate`, then build the **TailViewMac** and **TailViewIOS** schemes in Xcode. The project currently uses Alex's Apple development team and separate Mac/iOS bundle identifiers. Both devices must be signed in to Tailscale. The Mac needs Screen Recording and Accessibility permission, and iOS needs Microphone permission. Mac app and media sound is captured with ScreenCaptureKit; it does not need BlackHole. To use the incoming iPad or iPhone voice in a Mac app, install [BlackHole 2ch](https://github.com/ExistentialAudio/BlackHole) and select **BlackHole 2ch** as that app's input.

## First connection

1. Open TailView Mac. It starts sharing automatically and stays in the menu bar while running.
2. From its menu bar item, choose **Pair a New Device**. The settings window shows the Mac's Tailscale address and a temporary pairing code. Pairing closes after five minutes or after a successful pairing.
3. Open TailView on the iPhone or iPad, enter that address and code, and tap **Pair and connect**. This saves a random credential in the iOS Keychain. The Mac stores a digest in its Keychain.
4. Grant the initial system permissions. If macOS asks you to restart TailView after granting Screen Recording or Accessibility permission, relaunch it.

On later launches, the saved device connects without a code or a Mac approval click. The iOS app retries while it is foregrounded if the Mac host is temporarily unavailable. If a saved credential is rejected, pair again. The Mac menu bar item has **Pause Access**, which disconnects the viewer and stops screen capture, microphone return, and remote input. Pause remains in effect after relaunch until **Resume Access** is chosen. The Mac settings window can revoke a paired device.

## iPad and iPhone controls

The connected screen uses a compact bar above the system keyboard. The keyboard opens when the trusted Mac allows control; text and Backspace go straight to the focused Mac app without a local message field or Send button. Tap **Keyboard** to refocus it. Tap the Mac screen to click, two-finger tap to right-click, drag one finger to move the pointer, drag two fingers to pan, and pinch to zoom. The bar also offers click and drag controls; **More controls** includes scrolling, special keys, and zoom reset. TailView plays Mac sound and sends the iOS microphone by default. On iPad, playback follows the selected output, including AirPods; Settings shows the active output. iOS Settings can turn either audio direction off and can align the screen to the top.

The iOS software keyboard may be hidden when a hardware keyboard is attached or simulated. In Device Hub, **Device → Keyboard → Simulate Hardware Keyboard** must be off to see the software keyboard. Device Hub itself cannot show a physical iPad's screen while TailView has its microphone active. For screen and keyboard testing, open Device Hub before starting TailView. For microphone testing, quit Device Hub entirely and relaunch TailView on the iPad so capture starts with the physical microphone available. One launch immediately after closing Device Hub still measured silence; subsequent normal launches delivered audio after the screen session finished tearing down.

## Verification and limits

`scripts/test-transport.sh` checks pairing consent, saved reconnect, automatic control only for trusted devices, revocation, stopped-listener denial, session-code control denial, screen frames, microphone packets, trusted-viewer-only Mac audio packets, and viewport math. On the physical iPad, we verified that opening TailView connected to the running Mac host without a code, a running iPad session reconnected after the Mac host restarted, and the native keyboard appeared on cold launch without a local text field. Remote taps raised and focused a disposable TextEdit window, four onscreen key taps produced the exact text `test` in TextEdit, and Backspace changed it to `tes`. Mac app and media audio reached the physical iPad; after the audio-route fix, the app reported 10x AirPods Pro as output and audible playback through the AirPods was confirmed. The microphone started by default; with Device Hub fully quit, an independent eight-second BlackHole recording while AirPods playback was active measured mean -27.0 dBFS and peak -8.6 dBFS. With Device Hub's screen view open, the microphone path can measure digital silence. Pinch and two-finger pan still need direct fingers-on-device confirmation because Device Hub exposes only single-pointer input.

This is still a prototype. It captures only the main display as JPEG at up to 8 frames per second and 1280 pixels wide. Mac sound uses uncompressed 48 kHz stereo PCM over the same connection; audio compression, latency tuning, clipboard, files, and multiple monitors are not yet implemented. It has not undergone a full security review. It binds TCP port 47820 to the Mac's Tailscale IPv4 address, accepts one viewer at a time, and relies on Tailscale encryption. A saved Keychain credential can initiate a screen, sound, and control session whenever Mac access is on, so revoke lost devices and use **Pause Access** when access is not wanted.
